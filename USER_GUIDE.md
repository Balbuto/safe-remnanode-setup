> - **Настройка сервера** (из `Setup-and-Test-Server-Ubuntu-24`)

>
> Репозиторий: [github.com/Balbuto/safe-remnanode-setup](https://github.com/Balbuto/safe-remnanode-setup)

> Один файл, одно меню, одна команда — и сервер полностью готов к работе: оптимизирован, нода развёрнута, защита включена.

## 1. Что понадобится перед установкой

### Требования к серверу

| Требование | Значение |
|---|---|
| **ОС** | Ubuntu 24.04 LTS (рекомендуется) или Debian 11/12+ |
| **Права** | root (или пользователь с sudo) |
| **Архитектура** | amd64 (x86_64) или arm64 |
| **Минимум ресурсов** | 1 CPU, 1 ГБ RAM, 10 ГБ диска (для ноды лучше 2 ГБ RAM) |
| **Сеть** | Открытые порты 80/TCP, 443/TCP+UDP (для ноды); остальное скрипт настроит сам |
| **DNS** | A-запись домена ноды → IP сервера (если планируете VLESS+TLS или xHTTP) |

### Что нужно подготовить заранее

- **IP-адрес панели Remnawave** — адрес вашего основного сервера с панелью (не этого!)
- **Домен ноды** — например `node.example.com` (можно поддомен)
- **Secret key ноды** — выдаётся в панели Remnawave (раздел Nodes → создать ноду). Выглядит как длинная строка
- **Email** — для выпуска SSL-сертификатов Let's Encrypt (если нужен TLS)
- Для SSL через DNS-API: **Cloudflare API Token** или **Gcore API Token**

> ⚠️ **Важно:** скрипт меняет системные настройки (сетевой стек, файрвол, sysctl). Рекомендуется устанавливать на **свежий сервер** или сервер, на котором нет других критичных сервисов.

## 2. Установка скрипта

### Способ 1: скачать файл (рекомендуется)

```bash
wget https://raw.githubusercontent.com/Balbuto/safe-remnanode-setup/main/safe-remnanode-setup.sh
chmod +x safe-remnanode-setup.sh
sudo ./safe-remnanode-setup.sh
```

### Способ 2: одной строкой (curl | bash)

```bash
sudo bash -c "$(wget -qO- https://raw.githubusercontent.com/Balbuto/safe-remnanode-setup/main/safe-remnanode-setup.sh)"
```

Скрипт сам определит удалённый запуск, сохранит себя в `/usr/local/bin/safe-remnanode-setup` и откроет меню.

### Способ 3: клонировать репозиторий

```bash
git clone https://github.com/Balbuto/safe-remnanode-setup.git
cd safe-remnanode-setup
chmod +x safe-remnanode-setup.sh
sudo ./safe-remnanode-setup.sh
```

### Что произойдёт при первом запуске

1. Проверка прав root — если запущено не от root, скрипт откажется работать
2. Инициализация лога: `/var/log/remna-universal.log`
3. Настройка ротации общего лога (`/etc/logrotate.d/remna-universal`)
4. Регистрация глобальных команд:

```bash
safe-remnanode-setup   # главное меню (аналог: sudo ./safe-remnanode-setup.sh)
remnanode              # меню управления нодой
rkn-watcher            # меню управления защитой
```

5. Открывается главное меню.

## 4. Экспресс-установка: всё сразу

Пункт 1 главного меню (или команда `sudo safe-remnanode-setup express`) проводит полный цикл:

### Шаг 1/3 — Настройка сервера (автоматически)
- Обновление системы (`apt update`, `upgrade`, `dist-upgrade`)
- Установка базового софта (mc, net-tools, ncdu, iftop, curl, wget, git и др.)
- Установка Docker через официальный репозиторий
- Включение BBR + Cake qdisc
- Применение профиля ядра (автовыбор SAFE/HIGHLOAD по объёму RAM)
- Установка irqbalance
- Если система требует перезагрузки — скрипт предложит её сделать

### Шаг 2/3 — Установка ноды (интерактивно)
Скрипт спросит, перейти ли к установке ноды. **Подробное описание каждого вопроса — в разделе 6.**

### Шаг 3/3 — Установка защиты (интерактивно)
Скрипт спросит, перейти ли к установке RKN-Watcher. **Подробности — в разделе 7.**

> 💡 Если какой-то шаг не удался — экспресс не прерывается: скрипт предупредит и предложит повторить шаг позже из соответствующего пункта меню.

## 5. Модуль A: настройка сервера

Пункт 2 главного меню. Проводит базовую настройку **по шагам с вопросами** — вы выбираете, что делать:

```
БАЗОВАЯ НАСТРОЙКА СЕРВЕРА - выберите шаги

1. Обновить систему? [Y/n]
2. Установить базовый софт (mc, net-tools, ncdu, iftop, curl, wget, git)? [Y/n]
3. Установить Docker (apt + GPG)? [Y/n]
4. Включить BBR + Cake qdisc? [Y/n]
5. Hardening профиль: [s]afe / [h]ighload / [a]uto / [n]one
6. Установить irqbalance? [Y/n]
```

| Шаг | Что делает | Когда нужно |
|---|---|---|
| 1. Обновление | `apt update` + `upgrade` + `dist-upgrade` | Всегда при первом запуске |
| 2. Базовый софт | mc, net-tools, ncdu, iftop, curl, wget, git | Удобно для администрирования |
| 3. Docker | Официальный репозиторий docker.com, GPG-ключ, compose-плагин | Обязательно для ноды |
| 4. BBR + Cake | Включает TCP BBR и qdisc cake (файл `/etc/sysctl.d/99-bbr-cake.conf`) | Рекомендуется для VPN-нагрузки |
| 5. Профиль ядра | **SAFE** — консервативный; **HIGHLOAD** — для мощных серверов (nofile 1M+, conntrack 2M); **AUTO** — выбор по RAM (≥2 ГБ → HIGHLOAD); **none** — пропустить | AUTO — разумный выбор по умолчанию |
| 6. irqbalance | Распределение прерываний по ядрам CPU | Полезно на многоядерных серверах |

**Что ещё умеет модуль A:**

- **Пункт 8 главного меню — IPv6.** Отключение IPv6 (с бэкапом и скриптом отката `/root/restore-ipv6.sh`) или включение обратно. Отключение IPv6 рекомендуется для избежания утечек трафика.
- **Пункт 9 — UFW-менеджер.** Клонирует инструмент `Balbuto/ufw-manager`, показывает последние коммиты, предлагает проверить diff и запустить. Удобен для детальной настройки файрвола вручную.

**После завершения** скрипт покажет:
- Путь к бэкапам: `/root/remna-universal-backups/`
- Полный лог: `/var/log/remna-universal.log`
- Предложит перезагрузку, если она требуется

## 6. Модуль B: установка и управление нодой

### 6.1 Установка ноды (пункт 3 главного меню)

Скрипт проводит по этапам:

#### Этап 1 — Сетевая оптимизация и зависимости
Спросит: применить сетевую оптимизацию (BBR + sysctl профиль по RAM)? Рекомендуется **Y**.

#### Этап 2 — Версия Xray-Core
Спросит: выбрать версию Xray-Core из списка GitHub? При **Y** покажет список:

```
✨ ВЫБОР ВЕРСИИ XRAY-CORE
 1) Использовать версию из контейнера (по умолчанию)
 2) Xray-Core v26.7.28 [Pre-release]
 3) Xray-Core v26.7.11 [Pre-release]
 ...
```

- **1** — встроенная версия (самый безопасный выбор)
- Конкретная версия скачивается с GitHub и монтируется в контейнер

#### Этап 3 — Данные для связи с панелью

Скрипт по очереди спросит:

| Вопрос | Пример | Примечание |
|---|---|---|
| IP адрес панели Remnawave | `203.0.113.10` | IP **панели**, не этого сервера; используется для правил UFW |
| Домен ноды | `node.example.com` | A-запись должна смотреть на этот сервер |
| Порт управления нодой | `2222` (по умолчанию) | Порт, который панель использует для связи с нодой |
| **Сертификат ноды (secret key)** | длинная строка | Вставьте из панели; **завершите ввод двойным Enter** |

> ⚠️ Secret key выдаётся в панели Remnawave: Nodes → Create → скопируйте ключ. Если ввести пустой ключ — установка прервётся.

#### Этап 4 — Входящие порты для клиентов Xray
- Порты **80 и 443** открываются автоматически
- Дополнительно можно указать порты через пробел: `8443 2053 2083` — они будут открыты в UFW для входящих подключений клиентов

#### Этап 5 — Выбор протокола

```
Выберите тип шифрования клиентского трафика:
 1) VLESS Reality (маскировочный сайт / Selfsteal)
 2) VLESS+TLS (классический TLS с вашим доменом ноды)
 3) VLESS+TLS+xHTTP (новый высокопроизводительный транспортный протокол Xray)
```

| Протокол | Нужен домен? | Нужен SSL? | Особенность |
|---|---|---|---|
| **1. Reality** | Нет (используется чужой домен-маскировка, напр. github.com) | Нет | Самый защищённый от DPI; рекомендуемый |
| **2. VLESS+TLS** | Да | Да | Классика; трафик выглядит как HTTPS |
| **3. xHTTP** | Да | Да | Новый транспорт Xray, высокая производительность |

**Для Reality** спросит домен маскировки (decoy): по умолчанию `github.com` — на этот домен будет похож ваш трафик при проверке DPI.

**Для TLS/xHTTP** запустит выпуск SSL-сертификата:

```
🔐 ВЫБОР МЕТОДА ВЫПУСКА SSL СЕРТИФИКАТА
 1) Cloudflare API (DNS-01, wildcard *.домен)
 2) Certbot Standalone (HTTP-01, по 80 порту — стандартно)
 3) Gcore DNS API (DNS-01, wildcard *.домен)
```

| Метод | Что нужно | Когда использовать |
|---|---|---|
| Cloudflare API | API Token + домен на Cloudflare | Автообновление, wildcard |
| Standalone | Только email + открытый порт 80 | Проще всего, домен на любом DNS |
| Gcore API | API Token + домен на Gcore | Автообновление, wildcard |

После выпуска SSL настраивается автоматическое продление (renewal hook копирует сертификаты в ноду и перезапускает контейнер).

#### Этап 6 — Деплой и файрвол
- Генерируется `docker-compose.yml`: контейнеры **remnanode** + **remnawave-nginx** (маскировочный сайт)
- Скачивается и мутируется маскировочный шаблон (уникализация кода)
- Настраивается UFW: default deny incoming, SSH-порт определяется автоматически, 80/443, кастомные порты, **порт управления открыт ТОЛЬКО для IP панели**

**Результат:**
```
🎉   УСТАНОВКА И НАСТРОЙКА НОДЫ УСПЕШНО ЗАВЕРШЕНА!
Вы можете запускать это меню командой: remnanode
```

### 6.2 Меню управления нодой (пункт 5 главного меню / команда `remnanode`)

```
📌 Текущий статус ноды: Активна (Запущена)
 1) 🚀 Первоначальная настройка и запуск ноды
 2) 🔐 Выпуск и обновление SSL при смене домена ноды
 3) ⚡ Установка/Обновление кастомной версии Xray-Core
 4) 🔌 Смена IP адреса панели (Обновление правил UFW)
 5) 🔌 Управление клиентскими портами Xray и UFW
 6) 🎭 Смена маскировочного шаблона сайта (Selfsteal)
 7) 📊 Диагностика и просмотр логов ноды
 8) 🗑️  Полное удаление ноды с откатом всех изменений
 0) Назад
```

#### Пункт 2 — Смена домена ноды и SSL
- Вводите новый домен
- Скрипт перегенерирует маскировочный сайт
- Для TLS/xHTTP перевыпускает SSL (выбор метода заново)
- Перезапускает контейнеры с новым доменом

#### Пункт 3 — Обновление Xray-Core
- Заново показывает список версий с GitHub
- Скачивает выбранную и перезапускает ноду

#### Пункт 4 — Смена IP панели
- Показывает текущий разрешённый IP
- Вводите новый — скрипт удалит старое правило UFW и добавит новое

#### Пункт 5 — Управление клиентскими портами
```
 1) ➕ Добавить новый клиентский порт / диапазон портов Xray в UFW
 2) ➖ Удалить порт / диапазон из списка разрешенных
 3) 🔄 Принудительно перезагрузить правила брандмауэра (UFW reload)
```
- Можно добавить одиночный порт (`8443`) или диапазон (`2000:2010`)

#### Пункт 6 — Смена маскировочного шаблона
- **1** — случайный шаблон
- **2** — выбрать конкретный из 8 профессиональных шаблонов (игровые порталы, фоторедактор, киберспорт и т.д.)
- Каждый шаблон проходит мутацию (уникальные классы/хэши) — сайты не повторяются

#### Пункт 7 — Диагностика и логи
Показывает:
- Ресурсы сервера (CPU, RAM, диск)
- Статус контейнеров (remnanode, remnawave-nginx)
- Размеры логов

И позволяет:
```
 1) 📥 Лог запросов Xray (access.log) в реальном времени
 2) 📥 Лог ошибок Xray (error.log) в реальном времени
 3) 📥 Лог запросов веб-сервера Nginx в реальном времени
 4) 📥 Вывод логов из контейнера Docker (remnanode)
 5) 🔄 Вынужденно применить ротацию логов (logrotate)
```
> 💡 Выход из просмотра логов — **Ctrl+C** (прерывается только просмотр, меню остаётся).

#### Пункт 8 — Полное удаление ноды
- Останавливает и удаляет контейнеры и **образы Docker**
- Удаляет sysctl-оптимизации ноды и IPv6-конфиг
- **Сбрасывает UFW** (`ufw --force reset`) — учтите, сбросятся и другие правила
- Удаляет файлы ноды, логи, маскировочный сайт, logrotate, симлинк `remnanode`
- Требует подтверждения (y)

## 7. Модуль C: защита RKN-Watcher

### 7.1 Установка защиты (пункт 4 главного меню)

Скрипт:
1. Проверяет зависимости (iptables, ipset, curl, python3 и др.) — устанавливает недостающие
2. Проверяет поддержку ipset ядром (модуль xt_set)
3. Разворачивает файлы в `/opt/rkn-watcher/` (включая встроенные Python-хелперы)
4. Создаёт systemd-юниты: ежедневное обновление списков в 03:00 + восстановление правил после перезагрузки
5. Задаёт вопросы настройки:

```
Настройка области применения GeoIP:
1) Все порты
2) Один порт
3) Несколько портов
```

| Вопрос | Пояснение |
|---|---|
| Область GeoIP | На какие порты действует страновый фильтр (обычно «все порты» или 443) |
| Логирование RST-пакетов? | Записывать ли в лог сброшенные соединения (полезно для отладки) |
| Автообновление через systemd timer? | Обновление блок-листов каждую ночь в 03:00 |
| Включить TSPUBLOCK? | Блокировка сканеров ТСПУ (список CyberOK/Skipa) |
| Включить GOVIPS? | Блокировка сетей госструктур РФ |
| Включить GeoIP сразу? | Включить страновую фильтрацию |

6. Загружает блок-листы (несколько тысяч CIDR) и применяет правила

> ⚠️ Защита работает с **IPv4** (ipset поддерживает только IPv4).

### 7.2 Меню защиты (пункт 6 главного меню / команда `rkn-watcher`)

```
1) Блок-листы
2) GeoIP
3) Настройки
4) Статус
5) Логи
6) Переустановить / обновить
7) Удалить
0) Назад
```

#### Блок-листы
```
1) Вкл/выкл TSPUBLOCK
2) Вкл/выкл GOVIPS
3) Обновить оба списка
4) Показать правила / ipset
```
- Пункт 3 — ручное обновление списков прямо сейчас
- Пункт 4 — вывод цепочек iptables и наборов ipset с количеством записей

#### GeoIP — страновый фильтр
```
1) Вкл/выкл GeoIP
2) Добавить страну
3) Удалить страну
4) Добавить allow IP/CIDR
5) Удалить allow IP/CIDR
6) Добавить allow порт
7) Удалить allow порт
8) Добавить deny IP/CIDR
9) Удалить deny IP/CIDR
10) Добавить deny порт
11) Удалить deny порт
12) Показать конфиг
```
**Логика работы GeoIP (allow-список):** трафик из указанных стран пропускается, **все остальные — блокируются** (на выбранных портах). Плюс действуют deny-списки (IP/порты, которые блокируются всегда) и allow-списки (IP, которые пропускаются всегда).

> 💡 **Типовой сценарий:** панель доступна только из РФ → включить GeoIP, добавить страну `RU`, область применения — порт панели. Всё остальное будет отброшено.
>
> Код страны — двухбуквенный (ISO 3166): `RU`, `FI`, `DE` и т.д.

#### Настройки
```
1) Изменить FILTER_PORTS
2) Вкл/выкл LOG_RST
3) Вкл/выкл AUTO_UPDATE
4) Пере-применить правила
```
- FILTER_PORTS: `all` или список портов через запятую (например `443,8443`)
- AUTO_UPDATE: вкл/выкл ежедневного обновления списков

#### Статус
Показывает все настройки и счётчики:
```
TSPUBLOCK enabled : y
GOVIPS enabled    : y
GeoIP enabled     : false
Filter ports      : all
...
TSPUIPS entries   : 14587
GOVIPS entries    : 2311
GeoIP allow IPs   : 0
...
Timer: enabled
```

#### Логи
Просмотр `update.log`, `actions.log`, `geoip.log` или очистка всех логов.

#### Удаление
Полное удаление защиты: остановка timer/сервисов, **удаление правил iptables и наборов ipset**, удаление файлов. Требует ввода `YES`. Опционально удаляет пакеты, которые установщик доустанавливал.

 1) IP Region / Геолокация
 2) Censorcheck — геоблок
 3) Censorcheck — DPI
 4) iPerf3 — RU сервера
 5) iPerf3 — bench.tlab.pw (РФ)
 6) YABS

|---|---|

## 12. Безопасность и рекомендации

### Что скрипт делает для безопасности
- **Порт управления нодой** (2222) открыт в UFW **только для IP панели**
- UFW по умолчанию: `deny incoming` / `allow outgoing`
- SSH-порт определяется автоматически и не блокируется (защита от локаута)
- Все внешние скрипты качаются только по HTTPS
- Бэкапы всех изменяемых файлов перед правкой
- Secret key хранится в `.env` с правами 600 (только root)
- Повторная установка ноды требует подтверждения (чтобы не потерять ключ)

### Рекомендации после установки
1. **Смените SSH-порт** и включите вход по ключам (через ufw-manager или вручную)
2. **Проверьте статус защиты** через `sudo rkn-watcher status` — счётчики списков должны быть ненулевыми
3. **Проверьте ноду в панели** Remnawave: статус должен стать «активна»
4. **Настройте мониторинг** панели (Remnawave умеет слать алерты о недоступности ноды)
5. Периодически запускайте `sudo safe-remnanode-setup multitest` — особенно Censorcheck DPI, чтобы убедиться, что трафик не блокируется
6. Следите за обновлениями: `sudo remnanode` → пункт 3 (Xray), обновления панели — через панель

### Чего делать не стоит
- Не открывайте порт управления нодой для всех (правило UFW «только для IP панели» — это защита от атак)
- Не отключайте UFW без необходимости
- При полном удалении ноды помните: UFW сбрасывается полностью (`ufw --force reset`)

## 13. Частые вопросы и решение проблем

### ❓ Скрипт не запускается: «Должен быть запущен от имени root»
Запускайте с sudo: `sudo ./safe-remnanode-setup.sh`

### ❓ При установке защиты: «Ядро не поддерживает ipset»
Модуль xt_set отсутствует в ядре (часто в контейнерах/OpenVZ). Защита не сможет применять правила. На VPS/KVM-серверах обычно работает.

### ❓ Нода установлена, но в панели статус «неактивна»
1. Проверьте, что в панели указан **правильный IP и порт управления** (по умолчанию 2222)
2. Проверьте, что secret key совпадает
3. `sudo remnanode` → пункт 7 → убедитесь, что контейнер `remnanode` запущен
4. Проверьте UFW: порт управления должен быть разрешён **только с IP панели**

### ❓ Клиенты не подключаются
1. `sudo remnanode` → пункт 7 → посмотрите логи Xray (пункт 1/2)
2. Проверьте, что порт клиента открыт: `sudo ufw status`
3. Добавьте порт: `sudo remnanode` → пункт 5 → пункт 1
4. Проверьте Censorcheck DPI — возможно, провайдер режет протокол

### ❓ SSL не выпускается (Standalone): «Порт 80 занят»
Скрипт сам останавливает nginx/контейнеры перед выпуском и ждёт освобождения порта. Если не помогло — проверьте, что на 80 порту не висит другой сервис: `ss -tlnp | grep :80`

### ❓ После ребута пропали правила защиты
Должен сработать `rkn-watcher-boot.service`. Проверьте:
```bash
systemctl status rkn-watcher-boot.service
```

### ❓ Хочу отключить автообновление списков
`sudo rkn-watcher` → пункт 3 (Настройки) → пункт 3 (AUTO_UPDATE) → нет

### ❓ Как посмотреть, что делал скрипт?
```bash
tail -f /var/log/remna-universal.log      # общий лог
tail -f /var/log/rkn-watcher/update.log   # обновления списков
tail -f /var/log/remnanode/node/xray.err.log  # ошибки Xray
```

### ❓ Скрипт обновился — как получить новую версию?
```bash
sudo wget -qO /usr/local/bin/safe-remnanode-setup https://raw.githubusercontent.com/Balbuto/safe-remnanode-setup/main/safe-remnanode-setup.sh
sudo chmod +x /usr/local/bin/safe-remnanode-setup
```
